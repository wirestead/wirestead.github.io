01 / BUILT FOR CONNECTIONS

Less transport glue.
More application logic.

For applications that speak to serial sensors, TCP services and UDP telemetry feeds.

01

A consistent starting point

Configure each transport through builders and use a shared asynchronous model. Change the connection without rebuilding your application around a different API.

02

Give bytes a message boundary

Choose line-delimited, start/end pattern or length-prefixed framing. Add your own IFramer when your protocol needs it.

03

Make runtime behavior visible

Inspect runtime statistics and queue behavior. Callback-scoped data views make data ownership explicit; copy payloads when they need to outlive a callback.

02 / A FAMILIAR SHAPE

Build the connection.
Handle the data.

Set connection limits, attach a callback and build your client. The quick start shows a complete program and its lifecycle.

C++ quick start ↗
C++20 TCP CLIENT
auto client = wirestead::tcp_client("127.0.0.1", 8080)
    .max_retries(3)
    .connection_timeout(std::chrono::seconds(2))
    .on_data([](const wirestead::MessageContext& ctx) {
        std::cout << ctx.data().size() << " bytes\n";
    })
    .build();

Builder excerpt. Includes, startup and shutdown are shown in the quick start.
